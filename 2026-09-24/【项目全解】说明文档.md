## 〇、给接续 AI 的硬性规则（★新会话第一件事：读完本节）

这些规则来自用户（Tsinho）的明确要求，**不是建议，是必须执行**。历史上因为没执行，出过多次事故。

### 0.1 路径（最容易出事的一条）

**项目根目录 = `D:\Tsinho文件夹\新Tsinho黄油爬取工具`**

   - ② 为什么要这么改

## 一、项目是什么

### 1.1 一句话定位

**本地运行的 ACG 游戏资源聚合爬取工具**：从 5 个资源站抓取游戏信息，存进本地 SQLite，通过 Web 界面预览，并导出**可离线浏览的 HTML 卡片页**。

### 1.2 解决的问题

- 各站资源分散，人工翻找费时
- 只需要「有百度网盘 or 移动云盘」的资源（其余网盘不要）
- 需要一个带封面图、下载链接、解压码的**离线清单**，方便长期保存与分发给朋友

### 1.3 目标站点（5 个）

| 序号 | 站点 | 域名 | CMS / 技术 | 登录 | 爬取难度 |
|------|------|------|-----------|------|----------|
| 1 | ACG游戏姬 | www.acgyxjvip.com（备用 www.acgyxjvip2.com） | WordPress + Lolimeow | 不需要 | ★☆☆ |
| 2 | 萌幻ACG | bbs4.acgrx.com | Typecho + MiKu | **需要** | ★☆☆ |
| 3 | ACG图书馆 | acgll.xyz | WordPress + Zibll 8.8 | 不需要 | ★★☆ |
| 4 | ACG俱乐部 | www.acgjlb.cc | WordPress + Zibll | 不需要 | ★☆☆ |
| 5 | 鲲Galgame | www.kungal.com | Nuxt3 SSR + JSON API | 下载链接接口**需要** | ★★☆ |

> 已放弃：IACG.RIP / community.acg-c.net（Flarum，反爬 ★★★，暂不爬）

### 1.4 范围边界（明确不做的事）

- **不做**多用户、不做云端部署 —— 纯本地工具
- **不做**自动更新/自动分享 —— 爬取与导出都由用户手动触发
- **只保留**百度网盘 + 移动云盘（和彩云）两类链接，其它网盘（夸克/UC/115/迅雷等）一律跳过
- 鲲Galgame 是**唯一**「用户发帖」型站点，其余四站是**管理员整理**型站点 —— 这个区别影响备注的处理（见 5.4）

### 1.5 当前状态（2026-09-24）

- 处于**功能测试阶段，不是正式版**。用户明确口径：**看效果 1 页足矣，不要爬全库**（鲲全库约 342 页）。

  （平台分布：PC 511 / PC+安卓 415 / 安卓 48）

  - 主仓库 `origin` = `TKPORL/Tsinhohypqgj`，远端仍是 `5d59fbd`；本地 master 已归档 v14–v16 改动至 `a4b1823`（**未推送**）

## 三、怎么做的（架构）

### 3.1 整体架构

```
┌────────────────── 浏览器（原生 HTML/CSS/JS，无构建工具）──────────────────┐
│  爬取控制面板 │ 实时进度+日志 │ 结果卡片网格 │ 导出面板                     │
└───────────────────────────────┬──────────────────────────────────────────┘
                                │ fetch /api/*
┌───────────────────────────────▼──────────────────────────────────────────┐
│                       Flask 后端（app.py，924 行）                        │
│   API 路由 │ 任务线程管理 │ 导出调度 │ 图片代理(SSRF 防护)                 │
└──────────┬─────────────────────────────────────────┬─────────────────────┘
           │                                         │
┌──────────▼──────────────┐              ┌───────────▼──────────────────┐
│  爬虫引擎 CrawlerEngine  │              │  SQLite  data/crawler.db     │
│  crawler/__init__.py     │              │  posts / tasks               │
│  · 多站并发（每站独立线程）│              └───────────┬──────────────────┘
│  · 速度档位 stable/balance/fast         │
│  · 站内详情并发          │              ┌───────────▼──────────────────┐
│  · 增量跳过已入库        │              │  导出 generator/__init__.py   │
└──────────┬──────────────┘              │  三份 HTML + zip（含图片）    │
           │                             └──────────────────────────────┘
  ┌────────┴─────────┬──────────┬──────────┬──────────┐
  ▼                  ▼          ▼          ▼          ▼
acgyxj.py         acgrx.py   acgll.py   acgjlb.py  kungal.py
(HTML解析)        (HTML+登录) (HTML)     (HTML)     (JSON API + 登录)
  └──────── 全部继承 base.py 的 BaseCrawler ────────┘
```

### 3.2 数据流（一次爬取）

```
站点列表页 → 抓取帖子 URL 列表
   ↓ 逐条（站内并发）
详情页 → 解析标题/平台/点赞/图片/正文
   ↓ parser.extract_links_multi() 提取网盘链接（百度/移动，可含 PC/安卓 双份）
   ↓ 无百度且无移动云盘 → 跳过该帖
图片下载 → images/{source_id}/{md5}.webp（去重、本地化）
   ↓
database.insert_post() 写库（source + source_url 唯一判重）
   ↓
前端轮询 /api/progress 实时刷新日志与计数
```

### 3.3 核心模块

| 模块 | 文件 | 职责 |
|------|------|------|
| 调度引擎 | `crawler/__init__.py` | CrawlerEngine：多站并发、速度档位、增量判重、任务状态机 |
| 爬虫基类 | `crawler/base.py` | BaseCrawler：`_soup()` / `_fetch_with_retry()` / 验证页检测 / `CookieExpiredError` |
| 5 个站点爬虫 | `crawler/acgyxj.py` 等 | 各站选择器与解析规则（见「六、站点细节」） |
| 链接解析 | `parser/__init__.py` | `extract_links_multi()` 多链接提取、`fix_title_*()` 标题规范化、作弊码/云名提取 |
| 图片下载 | `parser/image_handler.py` | 连接池 Session、直连→代理→无 Referer 三级降级、MD5 去重、并发 6 |
| 数据库 | `database/__init__.py` | CRUD + `POST_ORDER_SQL` 统一排序口径 + `is_dual_netdisk()` |
| 导出 | `generator/__init__.py` | HTML 生成（内嵌 CSS/JS）+ 图片复制 + zip 打包 |
| 后端 | `app.py` | 全部 API 路由、线程管理、导出过滤条件 |
| 前端 | `static/app.js` + `style.css` + `templates/index.html` | 单页应用，无框架 |

### 3.4 排序口径（★改过多次，以当前为准）

**当前：纯「点赞降序 → id 倒序」**
- 统一实现于 `database.POST_ORDER_SQL`，SQL 侧与 Python 侧（`sort_posts()`）共用
- 涉及：`app.py::api_posts_grouped`、`database.get_posts`、`database.get_posts_by_crawl_id`、`generator.export_posts`
- **历史**：v8 曾用「双网盘优先 → 点赞降序」，v12 取消（会导致导出 HTML 排到一半"重新从高赞开始"，用户误判排序坏了）
- `is_dual_netdisk()` 保留但**不再参与排序**

### 3.5 平台判定

| 平台值 | 含义 | 导出归属 |
|--------|------|----------|
| `pc` | 仅 PC | PC下载 |
| `pc_android` | PC + 安卓 | PC+安卓下载 |
| `android` | 仅安卓 | 安卓下载（v14 起**不再**并入 PC+安卓） |
| `unknown` | 识别不出 | 归入 PC下载 |

- 各站判定优先从**标题**取（避免列表页分类误判）
- 鲲Galgame 由所选资源的 `platforms` 推得：`win→pc`、`and→android`、`两者→pc_android`、`emulator→pc_android`

## 四、数据怎么存

### 4.1 数据库位置与备份

- 主库：`acg_crawler/data/crawler.db`
- 自动备份：`acg_crawler/data/backups/crawler-YYYYMMDD-HHMMSS.db`（启动时距上次 >7 天自动备份，保留最近 10 份）
- 历史备份（现有）：`crawler-20260908-163619.db`、`crawler-20260917-134242.db`、`crawler-20260923-080343.db`、`before-clear-20260908-184912/`
- ⚠️ **任何数据库改动前必须再手工备份一份**

### 4.2 posts 表字段

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INTEGER | 主键 |
| source | TEXT | **来源站点中文名**（`ACG游戏姬` / `萌幻ACG` / `ACG图书馆` / `ACG俱乐部` / `鲲Galgame`）★判断站点必须用中文，不是 kungal 这种 key |
| source_id | TEXT | 原帖 ID |
| source_url | TEXT | 原帖链接（增量判重用） |
| title | TEXT | 标题 |
| platform | TEXT | pc / android / pc_android / unknown |
| content | TEXT | 正文/简介。**四站=游戏简介；鲲Galgame=清洗后的发布者备注** |
| likes / comments / views | INTEGER | 统计（当前仅 likes 有意义） |
| unzip_code | TEXT | 解压码（鲲按网盘标注） |
| cheat_code | TEXT | 作弊码 |
| baidu_link / baidu_code | TEXT | 百度网盘（兼容字段，保留第一条） |
| mobile_link / mobile_code | TEXT | 移动云盘（兼容字段） |
| download_items_json | TEXT | 多链接结构 `[{"provider","url","code","platform","label"}]`，PC+安卓帖最多 4 条 |
| images | TEXT | 本地图片路径 JSON 数组 |
| original_images | TEXT | 原始图片 URL JSON 数组 |
| crawled_at | TIMESTAMP | 爬取时间 |
| post_date | TEXT | 发布时间 |

### 4.3 images/ 与 output/

- `acg_crawler/images/{source_id}/{md5}.{ext}` —— **原始图片资产，不可重建**（重新下载需联网且原图可能已删）
- `acg_crawler/output/` —— **导出产物，可随时重建**，与数据库无关
  - 界面「删除该批次」**不动** output/
  - 代码有 `_cleanup_old_exports(keep=10)`，只保留最近 10 次导出
  - 单次导出可达数百 MB（zip 内含封面图）

### 4.4 增量爬取的判重逻辑

- 依据：数据库 `source` + `source_url`（`crawler/__init__.py::_url_exists`）
- **停止条件：连续 2 页帖子全部已入库才停**（不是碰到第一个已入库就停 —— 站点会把更新帖顶回列表页）
- **不读 output/**。库内数据一多，增量会立刻停 —— 要拉新数据用全量模式或先清库

## 五、视觉系统（★用户最关心的一块）

项目有**两套并列的皮肤**，必须同步维护：
1. **主界面** —— `acg_crawler/static/style.css`（+ `templates/index.html` 结构、`static/app.js` 行为）
2. **离线导出 HTML** —— 样式内嵌在 `acg_crawler/generator/__init__.py` 的 `HTML_TEMPLATE` 字符串里

### 5.1 当前风格 = Origin 深色编辑风（2026-09-23 替换）

> 参考 Origin Financial 的深色画廊 / 编辑排版语言

**核心规则：**
- **表面色阶代替投影**：`abyss #090a0b`（日志/批次底）→ `obsidian #0f1011`（画布）→ `graphite #2e2e2e`（卡片）→ `steel #3f4041`（hover）→ `silver #cacaca`（反转面，未用）。**卡片无 box-shadow、无上浮**
- **三声部字体**：
  - `--font-display` 衬线（Playfair Display / Noto Serif SC）→ **只做标题与统计大数字**，weight 300、行高 0.9–1
  - `--font-ui` 无衬线（Geist / Inter）→ 正文与控件
  - `--font-mono` 等宽（Roboto Mono）→ 所有标签、徽章、数据，**统一大写 + 0.182em 字距**
- **彩色使用规则**：`iris #847dff` / `cyan #00b3dd` / `orchid #dd90d8` / `deep-iris #4b49aa` **只用于满幅「分类色块」**（平台分组头 `.date-group-header[data-plat]`、导出卡片色块）；`cyan` 仅作数据信号（进度条、成功徽章）；**禁止彩色小字强调**
- **主操作 = 白底黑字**（带 `→`）；次操作幽灵描边；输入框黑底 + 1px `rgba(255,255,255,0.1)`
- 芯片统一胶囊（白色 12% 底 + 15% 描边）；顶栏吸顶 + `backdrop-filter: blur(24px)`
- 已**删除**：紫粉渐变、发光描边、Emoji 统计（❤ → `LIKE`）、卡片阴影与缩放大圆角
- 断点：900px / 560px / 390px，并统一处理 `prefers-reduced-motion`

**兼容设计**：`style.css` 里保留了**旧变量名作为语义别名**（`--bg-deep: var(--abyss)` 等），所以组件代码不用改。这给"只换变量表就能换肤"留了余地。

### 5.2 上一版风格 = 粉紫渐变深色主题（已存档，可切回）

> 2026-09-08 之前使用，2026-09-23 被 Origin 替换

- 主色 `--accent: #e056a0`（粉红），渐变 `--grad-1: linear-gradient(135deg, #e056a0, #8b5cf6)`（粉→紫）

### 5.4 ★卡片「备注」规则（2026-09-23 定案，曾改错）

- **只有鲲Galgame 的卡片显示「备注」块**，其余四站**不显示**
- 原因：四站是**管理员整理**型，`content` 装的是**游戏简介**，不是发布者备注；鲲是**用户发帖**型，用户会写改后缀/解压工具等说明，这才叫备注
- 判定条件（两处都必须有）：
  - `generator/__init__.py`：`if note_text and post.get("source") == "鲲Galgame":`
  - `static/app.js`：`if (noteText && post.source === "鲲Galgame")`
- ⚠️ 曾经写成 `== "kungal"`（英文 key），**永久不成立**，导致鲲备注全都不显示。`source` 字段存的是**中文名**
- 备注块交互规格：
  - 默认显示 3 行，超出才出现「展开」按钮；展开高度**取实测值**（不猜固定 max-height），动画收尾清掉内联高度
  - 箭头随状态 `rotate(180deg)`；`aria-expanded` / `aria-label`（展开备注 / 收起备注）；原生 `button` 键盘可触发；`prefers-reduced-motion` 下取消动画
  - 卡片在折叠分组里时高度量为 0 → 用 `IntersectionObserver` 等真正可见再判定是否显示按钮
  - `[hidden]` 需显式 `display:none`，否则会被 `.note-toggle{display:inline-flex}` 覆盖
  - **整块点击复制**：`data-copy` 存**完整备注**（非截断文本）；导出侧在 Python 里就把 `data-copy` 中的「网盘大小」行剔除，前端 `copyNote` 再过滤一次

### 6.5 鲲Galgame（kungal.py，671 行，最复杂）
- **全 JSON API，不走 HTML 解析**：
  1. 列表 `/api/galgame?include_providers=baidu,caiyun&page=N&limit=20` ★ 参数必须 **snake_case**，驼峰会被静默忽略
  2. 游戏详情 `/api/galgame/{gid}` → 主名/原名/别名/主封面/简介/点赞
  3. 资源列表 `/api/galgame/{gid}/resource/all` → 每条资源的网盘、平台、大小、`status`(0有效/1失效)、备注
  4. 下载详情 `/api/galgame-resource/{rid}/detail` → `link[]`/`code`/`password`（**需登录 cookie**）
- **登录**：NextMoe·未萌 OAuth，会话 cookie 存 `.env: KUNGAL_COOKIE`（约 90 天**滑动**有效，期间爬过自动续期）；失效抛 `CookieExpiredError`
- **一键刷新 cookie**：`C:/Python314/python.exe tools/refresh_kungal_cookie.py`（约 42 秒，读 `.env` 的 `NEXTMOE_NAME`/`NEXTMOE_PASSWORD`）
  - 已挂定时任务「刷新鲲Galgame登录cookie」：每 60 天一次（首次 2026-11-22 09:00）
- **挑选规则**：只保留百度/和彩云，每类取"有效资源里最新"一条；都没有则跳过该游戏
- **标题**：只写主名 + 【平台】，**不写大小**（各盘体积不同，写一个会误导）；大小移到备注「网盘大小」行
- **备注结构**（`_build_content`）：`网盘大小：百度网盘 x ｜ 移动云盘 y`（**必须放第一行**，否则长别名会把它挤到折叠线以下）→ `别名：<原名并入同行>` → `【百度网盘 发布者备注】` → `【移动云盘 发布者备注】` → `【简介】`（总长截 5000）
- **解压码**：取 `password`，**按网盘标注**（`百度网盘 open ｜ 移动云盘 afggacg`；同码合并；单盘只写该盘）；备注里"解压密码"行自动删除并重排序号
- **引流清洗**（★通用规则，不是背句子）：
  - `_is_promo_line()` / `_promo_rule()` 7 类规则：①整行裸链接 ②命中外部域名（夸克/B站/docs.qq/slpeey/115/123pan 等）③社群·教程·工具汇总关键词 ④带链接+工具/教程词 ⑤"请查看/详见/自取"收尾的引导句 ⑥纯 QQ 号 ⑦图片被丢弃后残留的单行"PC/安卓/游戏截图"
  - `_collapse_numbered_groups()`：编号列表整组丢弃，组上方引导句一并丢弃
  - `_strip_html()`：`<br />` 当换行、去其余标签、**清零宽字符与方向控制符**
  - ★ **零宽字符坑**：原文夹 `\u200b`，`'PC\u200b'` 这类短行匹配不上 → 必须先清零宽/方向控制符再判断
  - 审计日志：`logs/promo_clean/YYYY-MM-DD.jsonl`，记 `removed`（删了什么+命中规则）+ `suspect`（漏删候选）
  - 已发现误删：含"苹果PC安装也有详细教程"的真实解压说明被规则③误杀，**待调阈值**
- 末页返回空 JSON（<200 字符），会被基类"验证页检测"误判 → kungal 改为自己发请求（`_api`），不套用该启发式（见 README v11）
- **重爬脚本**：`tools/recrawl_kungal_full.py`（带 `--start`/`--end`）。★ 改完爬虫**必须用脚本重爬**，界面按钮跑的还是常驻进程里的旧代码
