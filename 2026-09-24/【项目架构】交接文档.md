## 一、项目目标

本地运行的ACG游戏资源聚合爬取工具，从多个站点抓取资源信息，提供Web界面预览，并支持导出离线HTML文件。

## 五、核心模块说明

### 5.1 爬虫模块 (crawler/)

**BaseCrawler** (base.py)：
- 抽象基类，定义爬虫接口
- 内置 `_soup()` 方法（SSL验证关闭、超时、重试）
- 内置 `_fetch_with_retry()` 方法（指数退避重试）

**ACGYXJCrawler** (acgyxj.py)：
- 主域名失败自动切换备用域名
- 标题格式化：`[新作/类型] 游戏名 [平台 大小] [云名]`
- 云名清理：`PCC152888` → `C155555`（去除PC前缀）
- 统计提取：浏览量(span.view)、点赞(span.like-count)、评论(single-meta-box文本)
- 平台检测：优先从标题判断，避免分类误判

**ACGRXCrawler** (acgrx.py)：
- 需要登录（邮箱+密码）
- 登录后保持Session
- 解压码从正文提取（正则匹配）

**ACGLLCrawler** (acgll.py)：
- 无解压码（固定为空）
- 图懒加载：`data-src` 属性

**ACGJLBCrawler** (acgjlb.py)：
- 列表选择器：`div.item-body > h2.item-heading > a`
- 过滤置顶帖（根据标题关键词）
- 固定解压码：`007721`

**KungalCrawler** (kungal.py)：
- 不走 HTML 解析，全部用 JSON 接口（详见【技术方案】交接文档 4.5 节）
- 列表 `/api/galgame?include_providers=baidu,caiyun`（参数必须 snake_case）
- 每个游戏额外 2~4 次请求：游戏详情 + 资源列表 + 每个网盘各一次下载详情
- 下载链接接口需登录：会话 cookie 从 `.env` 的 `KUNGAL_COOKIE` 读（约90天有效，失效抛 `CookieExpiredError`，日志提示重新登录）
- 每网盘只取"有效资源里最新"的一条；解压密码进 `unzip_code`，备注里对应行删除并重排序号
- 封面只取 1 张（`effective_banner_url`）

### 5.2 图片处理 (parser/image_handler.py)

- 共享 `requests.Session`（连接池：20连接）
- 下载顺序：直连 → 代理 → 无Referer直连
- 文件名：URL的MD5哈希 + 原始扩展名
- 最小文件：500字节（小于视为失败）
- 并发下载：`max_workers=6`

### 5.3 导出模块 (generator/)

- HTML模板：暗色主题（**当前 = Origin 编辑风**：色阶分层、无投影、等宽大写标签；★旧「粉紫渐变」风格已存档于 `docs/风格存档/旧版-粉紫渐变/`，可切回）、卡片网格布局
- ★ **导出皮肤的样式内嵌在 `generator/__init__.py` 的 `HTML_TEMPLATE` 字符串里**；改视觉要与 `static/style.css`（主界面）**两处同步**
- ★ **卡片「备注」块仅鲲Galgame 显示**（判定 `post.source == "鲲Galgame"`，必须用中文名）；四站 `content` 是游戏简介，不显示
- 导出拆三份：PC下载 / PC+安卓下载 / 安卓下载（单安卓独立，不再并入 PC+安卓；某类为空则不生成）
- 图片：复制到output目录，使用相对路径引用
- 打包：zip格式（HTML + images目录）
- 平台分类：PC / PC+安卓 / 安卓

### 5.4 数据库 (database/)

**posts表**：
| 字段 | 类型 | 说明 |
|------|------|------|
| id | INTEGER | 主键 |
| source | TEXT | 来源站点 |
| source_id | TEXT | 原帖ID |
| source_url | TEXT | 原帖链接 |
| title | TEXT | 标题 |
| platform | TEXT | 平台：pc/android/pc_android |
| content | TEXT | 正文内容 |
| likes | INTEGER | 点赞数 |
| comments | INTEGER | 评论数 |
| views | INTEGER | 浏览量 |
| unzip_code | TEXT | 解压码 |
| cheat_code | TEXT | 作弊码 |
| baidu_link | TEXT | 百度网盘链接（兼容字段，保留第一条） |
| baidu_code | TEXT | 百度提取码（兼容字段） |
| mobile_link | TEXT | 移动云盘链接（兼容字段） |
| mobile_code | TEXT | 移动提取码（兼容字段） |
| download_items_json | TEXT | 多链接结构（[{"provider","url","code","platform","label"}]），ACG游戏姬 PC+安卓 帖子可含 4 条 |
| images | TEXT | 图片路径（JSON数组） |
| original_images | TEXT | 原始图片URL |
| crawled_at | TIMESTAMP | 爬取时间 |
| post_date | TEXT | 发布时间 |

**tasks表**：记录爬取任务历史

## 八、已知问题与注意事项

1. **评论数据**：所有站点评论/浏览量已移除，仅保留点赞数
2. **图片下载**：需要网络正常，CDN图片通常可直连
3. **代理**：config.yaml中默认开启，Clash未运行时需关闭或直连
4. **ACG俱乐部**：固定解压码007721
5. **置顶帖过滤**：各站通过标题关键词过滤（教程、合集、工具、必看等）
6. **标题处理**：`fix_title_tags()`自动检测额外标签移到开头【】，`fix_title_brackets()`统一【】括号
7. ★ **`萌幻ACG` 点赞恒为 0**：该站 192 条记录 `likes` 全部是 0，点赞解析未生效（`crawler/acgrx.py` 需补选择器）。因为排序里点赞是第二优先，这 192 条会永远沉底，且「点赞高」的筛选对它们无意义。**未修，待确认该站页面是否有点赞元素**
8. **各站点赞数不在同一量级**：ACG图书馆 5–16、ACG游戏姬 0–14、ACG俱乐部 0–143、萌幻ACG 全 0。跨站比赞数没有可比性，排序结果里高赞几乎都来自 ACG俱乐部。若需要「按站内热度」而非「原始赞数」，得先做归一化（未做）
9. **排序口径已变更（2026-09-23）**：现行是纯「点赞降序 → id 倒序」。旧规则「双网盘优先 → 点赞降序」会让导出 HTML 到第 N 张时从高赞重新开始（用户误以为排序坏了），已取消；`is_dual_netdisk()` 保留但不再参与排序
10. ★ **鲲Galgame 登录 cookie 会过期**：下载链接接口依赖 `.env` 的 `KUNGAL_COOKIE`（约90天**滑动**有效，期间爬过就自动续期）。过期后该站整体报错（`CookieExpiredError`，日志有明确提示），跑 `python tools/refresh_kungal_cookie.py` 即可自动重新登录并刷新（需要 `.env` 里有 `NEXTMOE_NAME` / `NEXTMOE_PASSWORD`）。**未做定时自动刷新**

## 十、更新记录

### 2026-09-20 v8 结果排序：双网盘置顶 + 点赞降序
- **需求**：用户反馈「双网盘没有在最顶部」，要求点赞高的双网盘排最前，公式写作「双网盘（赞高）-单网盘（赞高）-双网盘（赞低）-单网盘（赞低）」
- **歧义澄清**：该公式（点赞优先、同赞内双网盘靠前）与「双网盘在最顶部」互相矛盾——库里双网盘最高只有 16 赞、单网盘最高 143 赞，点赞优先的话顶部**依然全是单网盘**。已向用户出示两种规则的真实 Top12 并让其选择，用户选定**双网盘为第一优先**
- **最终排序**：`双网盘优先 → 点赞降序 → id 倒序`
- **共享口径**（关键，避免两边漂移）：`database/__init__.py` 新增
  - `DUAL_NETDISK_SQL`：`CASE WHEN baidu_link<>'' AND mobile_link<>'' THEN 0 ELSE 1 END`
  - `POST_ORDER_SQL`：`ORDER BY DUAL_NETDISK_SQL, COALESCE(likes,0) DESC, id DESC`
  - `is_dual_netdisk(post)` / `sort_posts(posts)`：Python 侧同口径 + 排序
- **改动位置**：
  - `app.py`：`api_posts_grouped`、`_fetch_filtered_posts` 改用 `POST_ORDER_SQL`（原先是 `post_date DESC, id DESC` / `likes DESC`）
  - `database/__init__.py`：`get_posts`、`get_posts_by_crawl_id` 改用 `POST_ORDER_SQL`
  - `generator/__init__.py`：新增 `from database import sort_posts`，`export_posts` / `export_posts_filtered` 由 `sorted(key=likes)` 改为 `sort_posts(posts)`——**这修掉了导出 HTML 与页面排序不一致的问题**
- **口径核对**：`baidu_link+mobile_link` 与前端渲染按钮用的 `download_items_json` 全库 804 条**零不一致、零缺失**
- **验证**：新增 `acg_crawler/_test_sort_order.py`，全通过（全库 476 双 / 328 单、分界在第 477 条、SQL 与 Python 序列完全一致、结果页 3 页每组有序且跨页连续无重复、批次 57、导出 HTML 点赞序列）；浏览器实测结果页首屏为双网盘卡片、赞 16/15/15…降序
- **踩坑记录**：测试里一度把接口返回的**分组结构**拉平后断言「整体有序」而失败——结果页顺序是「逐组展示」，有序性只在组内成立，跨组拼接本就不该有序。是断言写错，不是代码问题
- **已知未修**：`萌幻ACG` 192 条 likes 恒为 0，会永远沉底（见「八、已知问题」第 7 条）

### 2026-09-20 v7 爬取控制：站点选择合并 + 每站独立页码范围

- **未改动**：`crawl_by_date` / `crawl_incremental` 仍用站点列表，`delete_and_recrawl` 走增量模式不受影响

### 2026-09-20 v6 结果页点赞降序修复
- **现象**：网页「爬取结果」面板帖子顺序与点赞无关，用户反馈"像随机排列，没实现点赞高低排序"
- **根因**：结果页接口 `GET /api/posts_grouped`（`app.py`）的 SQL 排序键为 `COALESCE(NULLIF(post_date,''),SUBSTR(crawled_at,1,10)) DESC, id DESC`，完全不含 `likes`
- **修复**：三处 SQL ORDER BY 统一改为 `COALESCE(likes, 0) DESC, id DESC`
  - `app.py` → `api_posts_grouped`（结果页，分页 60 条/页）
  - `database/__init__.py` → `get_posts`（`/api/posts`、`/api/export` 使用）
  - `database/__init__.py` → `get_posts_by_crawl_id`（`/api/export_batch`、历史批次跳转结果页）
- **设计说明**：保留 `id DESC` 作二级键，避免同点赞数时排序不稳定导致分页漏条/重复；平台分组逻辑未动（先 SQL 排序 → 再按 platform 分桶 → 组内顺序即点赞降序）
- **范围确认**：离线导出 HTML 走 `generator.export_posts` / `export_posts_filtered`，本就 `sorted(key=likes, reverse=True)`，实测导出文件点赞序列 14,14,12,12,11…0 已正确，无需改动
- **验证**：Flask test_client 实测全部/PC/PC+安卓三组点赞序列严格降序；第 1 页 16→12、第 2 页 12→9 衔接连续；批次视图 batch=56（197 条）同为降序
- **未改动**：`_fetch_filtered_posts`（导出用，末段仍按日期取数，导出层会重新按点赞排序）
