## 二、二狗ACG（2gouacg.com）—— 无门槛，可先接

### 2.1 站点基本情况
- WordPress，TouchGal 风格主题；文章作者"王二狗子"。
- 游戏资源分类 `?cat=3`；另有 `?cat=2`（广告分类，不爬）。
- 详情页 URL：`https://2gouacg.com/?p={ID}`（数字 ID）。
- 无登录墙、无回复可见，**网盘链接明文写在 HTML 里**。
- 列表页每帖带浏览量（如 2.76k）与发布日期。

### 2.2 URL 与分页（已实测）
- 列表：`https://2gouacg.com/?cat=3`
- 分页：`https://2gouacg.com/?cat=3&paged=2` ✅ 实测有效（`&page=2` 也可用，统一用 `paged`）

### 2.3 详情页内容结构（实测 ?p=17969、?p=17895）
- 正文分段：`▼ 游戏概述`（含"PC+安卓双端可分开独立下载的哦~"/"只有PC哦~"字样）、
  `▼ 游戏介绍`、`▼ 游戏截图`、`▼ 更新日志`、`▼ 下载地址`。
- 下载区：**明文 `<a href>`**，百度 + UC 并列；例：
  - `https://pan.baidu.com/s/1c6cAPY9DwA7C6iVCZyAoBQ?pwd=gkef`
  - `https://drive.uc.cn/s/5975d317d6f94`（过滤掉）
- 一个帖可能有多条百度链接（实测 ?p=17895 有 2 条百度 + 1 条 UC，即 PC / 安卓 各一条）→
  正好复用现有多链接结构（download_items_json，PC 一条安卓一条）。
- 解压密码：每帖标注，实测值都是 `twodog`（站方统一密码，帖内写"解压密码：twodog"）。
- 平台判定：
  - **PC+安卓 的游戏，标题里写**（"PC+安卓双端"）；
  - **只有 PC 的游戏，标题里不写平台**，要读正文"只有PC哦~"来判定 PC（用户 2026-09-24 明确）。
- 演示视频：帖内可能夹杂，**不爬**；只爬全部图片。

### 2.4 标题改写规则（用户 2026-09-24 给的两个标准例）

规则要点：
① 首部【标签组】里的"中文"与后面正文的"官方中文版/汉化版"等合并进标签；
② 多个游戏名之间的 `/` 分隔改为空格；
③ 删掉"PC+安卓双端"/"百度+UC"字样；
④ 体积保留，与平台合成尾部标签 `【PC+安卓 758M】` / `【PC 1.59G】`；
⑤ "更新"/"新作"等前缀保留。

例 1（PC+安卓）：
- 原标题：`【日式RPG/中文/动态】命运束缚的公主/宿命哀吟 姫ハ運命ニ呻吟ヘリ/Destined Damsel In Distress V1.05 PC+安卓双端官方中文版 百度+UC/758M`
- 改为：`【日式RPG/中文/动态/官方中文版】命运束缚的公主 宿命哀吟 姫ハ運命ニ呻吟ヘリ Destined Damsel In Distress V1.05 【PC+安卓 758M】`

例 2（仅 PC，平台词不在标题）：
- 原标题：`更新【日式互动SLG/中文/动态】救生员狂热/Lifeguard Holic V1.4 官方中文正式版+存档 百度+UC/1.59G`
- 改为：`更新【日式互动SLG/中文/动态/官方中文正式版+存档】救生员狂热 Lifeguard Holic V1.4 【PC 1.59G】`

细节确认：
- 例 2 尾部是 `【PC 1.59G】`（两个空格在后缀前，导出时可归一化为单空格）。
- PC 游戏的体积同样取标题尾 `百度+UC/1.59G` 的数字；若某帖标题没有体积段，需降级
  （正文找或留空，待遇到再定）。

### 2.5 接入方式
按四站 HTML 模式写 `crawler/2gou.py`（命名待定）：
- 列表 `?cat=3&paged={n}` 解析帖子链接 `?p={ID}` + 标题；
- 详情解析：标题改写（2.4）、正文图片（跳过视频）、"只有PC哦~"/标题双端词判平台、
  明文百度链接提取（pwd 参数即提取码）、解压密码 twodog、体积；
- 反爬：无（实测裸请求即可，仍建议限速 1-2 秒/请求）。

## 三、玖黎ACG（jiuliacg.com）—— 有硬门槛，方案待定

### 3.1 站点基本情况
- WordPress + **子比主题（zibll）**（版权声明/`posts-copyright`、`signin-loader` 等 DOM 特征）。
- 分类：`/pc`（电脑游戏）、`/手机游戏`（中文 URL，需编码）；另有 `/galgame` 标签分类。
- 详情页 URL：`https://jiuliacg.com/archives/{数字ID}`。
- 列表卡片标题自带平台标签：【PC / 安卓 / 汉化】、【PC / KR / 汉化】等，作者统一"绯玉丸"。
- 解压密码：**不逐帖标**，统一写在网站公告（"解压码等各种问题请阅读网站公告及新手必读"）。

### 3.2 下载链接的门槛（实测 /archives/6327）
- 未登录状态下，**整页 HTML 里没有任何 pan.baidu / 夸克 / 蓝奏链接**。
- 下载区显示："**此处内容已隐藏，请评论后刷新页面查看**"——子比主题"评论可见"功能。
- 即：拿链接必须 **登录 + 在帖内评论**（评论是公开可见行为）。

### 3.3 反爬（实测）
- 裸 `urllib` 连续请求第二次即 **403**；带完整浏览器头（UA/Accept/Accept-Language/Referer）
  + 每请求间隔数秒可正常访问。
- 接入必须限速 + 完整请求头，或直接走浏览器方案。

### 3.4 登录可行性（2026-09-24 实测）
- 标准 `wp-login.php` 表单登录**不可用**：登录页无 log/pwd 字段（zibll 用弹窗 AJAX 登录）。
- 主题 AJAX 端点为 `admin-ajax.php` + `zib_*` 系列 action（zibll 主题惯例，如 `zib_user_signout`），
  登录 action 的确切参数还需抓登录请求包确认。
- 用户已提供账号（存 `.env` 的 `JIULIA_USERNAME` / `JIULIA_PASSWORD`）。
- **结论：模拟真人操作可行，用户 2026-09-24 已拍板走鲲同方案**（agent-browser 真实浏览器登录维持会话）。
- **自动评论已获用户批准**：评论输入框自带模板文字，**不需要输入内容、直接点"提交评论"**即可，爬一帖评一帖。
- HTTP 纯请求路线备用：抓包确认 `zib_*` 登录 action 后可全程无浏览器，但被 WAF 盯上风险更高。

## 六、玖黎滑块验证实测记录（2026-09-24 晚，agent-browser 实测）

### 已验证可行
1. **登录弹窗/表单/提交按钮全部定位成功**：可见表单字段 `input[name=username]` / `input[name=password]`，
   提交按钮 `button` 文本"登录" type=button（排除 `.signin-loader`）。
   ⚠️ DOM 里有登录+注册两套表单，必须按 `getBoundingClientRect().width` 过滤可见的那套再赋值。
2. **滑块（拼图）验证可以自动过**：定位方法 = 从 bar 画布取拼图形素（alpha>128），
   与 bg 画布全位置做**亮度 Pearson 相关**，r≈0.53 处即洞位置（实测 bdx=194 一次通过）。
   拖动需**实时校准缩放**（手柄 60px ≈ 拼图 55px，比率 0.917），轨迹用"快-慢-过冲回拉"+y 抖动。
   CDP 真实鼠标事件（mouse move/down/up）能被验证接受，已实测滑层消失。
3. 工具脚本：`C:/Users/Administrator/.workbuddy/binaries/slider_gap.py`（边缘对解析，备用）。

### 未解决（下次继续）
1. 滑块通过后**登录未生效**（无 `wordpress_logged_in` cookie，页面无 Tsinho）——
   待查：密码是否正确（.env `JIULIA_PASSWORD`）/ 是否需邮箱登录 / 提交后 toast 已错过。
   下次重跑时在滑块通过后 1 秒内抓 toast 文本。
2. **登录弹窗会"卡死"**：页面停留久了 JS click 和真实点击都打不开弹窗；
   整页 `open` 刷新后恢复。爬虫要做成"每轮操作前先刷新页面"。
3. 失败重试次数多（滑块拖错会刷新图片），需控制频率防风控。

### 登录成功后的下一步（已探测）
- 评论框只有**登录后**才渲染（未登录页面无 textarea，`提交评论`按钮也不存在）。
- 评论流程：textarea 填模板 → 点"提交评论" → 又弹同一滑块 → 同法拖过 → 评论发出。
- 评论后页面出现 pan.baidu 链接（隐藏内容解锁），直接从 HTML 提取。
