# 项目完整修复与测试总方案

> 项目：ACG 黄油资源聚合爬取工具  
> 建立日期：2026-09-08  
> 状态：执行中  
> 用途：跨会话总控、问题追踪、实施记录和最终验收

## 一、总目标

对当前工具进行一次完整的正确性修复、稳定性改造、性能优化和用户体验升级。任何后续对话均以本文件为主要执行清单，避免会话中断、切换或上下文丢失后遗漏工作。

最终目标：

1. 四个站点均能稳定抓取有效游戏资源。
2. 点赞、下载链接、平台、图片、标题和解压信息尽可能准确。
3. 选择多个站点后真正并行爬取，并分别显示独立状态窗口。
4. 提高爬取速度，同时控制限流、漏抓和数据库写入风险。
5. 主界面及离线导出页面支持点击图片查看大图。
6. 修复任务状态、代理、调试模式、敏感配置和运行产物管理问题。
7. 对现有数据库执行只读审计，未经用户确认不删除历史数据。
8. 对代码、数据链路和完整用户流程分别检查三遍、测试三遍。
9. 每完成一个阶段，立即更新本文件、README、交接文档和项目工作日志。

## 二、已确认的问题清单

### P0：结果正确性

#### 2.1 点赞数量大量为 0

需要逐站确认：

- 原站是否提供点赞、评论、浏览量或其他热度字段。
- 列表页和详情页选择器是否仍然有效。
- 数字是否支持 k、w、万及带小数格式。
- 数据是否在解析、入库或 API 返回过程中丢失。
- 萌幻 ACG 等本身没有点赞数据的站点，不应把“未知”伪装成真实的 0 点赞。
- 排序不能让无热度数据的站点永久沉底。

验收要求：有真实数据的站点正确提取；没有数据的站点明确显示“暂无数据”或采用统一备用排序，不伪造点赞数。

#### 2.2 卡片缺少下载链接

完整检查链路：

1. 原帖是否存在百度网盘或移动云盘链接。
2. 隐藏区、按钮属性、脚本文本和正文中是否存在链接。
3. 链接正则是否覆盖完整 URL、查询参数、/#/ 路径和 HTML 转义。
4. 提取结果是否写入数据库。
5. API 是否完整返回字段。
6. 前端是否正确渲染百度和移动云盘按钮。
7. 离线导出是否保留按钮及提取码。

重点审计“有解压码但没有下载链接”的记录。新抓取数据没有有效下载链接时不得入库；现有历史数据只生成报告，不直接删除。

#### 2.3 ACG俱乐部数据在页面不可见

数据库已有 ACG 俱乐部记录，因此同时检查：

- 列表页选择器和帖子 URL 过滤规则。
- 详情页内容、隐藏链接及点赞选择器。
- source_id 生成规则。
- platform 分类，尤其是 unknown。
- crawl_id 批次归属。
- 来源筛选和平台筛选。
- API 分组与前端渲染。
- 固定解压码 007721 的处理是否影响过滤。

验收要求：单独选择 ACG俱乐部可抓到结果；四站同时抓取后可在来源筛选和对应平台组中查看。

### P1：功能与界面

#### 2.4 图片点击查看大图

主页面和离线导出页面均增加图片灯箱：

- 点击缩略图打开大图。
- 支持同一卡片多图左右切换。
- 支持键盘左右方向键。
- 支持 Esc 关闭。
- 支持点击遮罩关闭。
- 显示当前张数。
- 图片加载失败时显示友好提示。
- 移动端可正常查看。

#### 2.5 四站并行、四个独立状态窗口

当前后端已在站点层使用线程池并发，但日志和统计混在一起。目标设计：

- 选择几个站点就创建几个站点状态面板。
- 每个面板独立显示等待、运行、完成、失败、停止和降速状态。
- 每站独立显示当前页、处理量、成功、跳过、错误和日志。
- 页面顶部保留总体汇总。
- 一个站点失败不影响其他站点。
- 全部站点完成后再跳转结果页。
- 第一阶段提供停止全部；后续评估是否增加单站停止。

#### 2.6 标题和卡片布局

- 长标题支持完整查看，不能只能看到截断内容。
- 点击标题复制功能继续保留。
- 卡片采用内容自适应高度，减少无意义空白。
- 多图区域比例统一，不拉伸原图。
- 下载按钮、解压码、作弊码和原帖按钮布局稳定。
- unknown 平台需要重新识别，尽量不长期显示为“其他”。
- 没有真实点赞数据时不显示误导性的“0点赞”。

### P1：性能与稳定性

#### 2.7 爬取速度优化

专项细节见《【爬取性能优化】实施方案.md》。总方案要求：

- 保留四站并发。
- 增加受控的站内详情并发。
- 默认平衡模式：ACG游戏姬 3，其余站点 2。
- 图片下载与核心详情解析解耦。
- 图片使用全局固定后台队列。
- 提供稳定、平衡、快速三档。
- 快速模式遇到异常自动回落。
- 设置全局硬并发上限，不能无限创建线程。

#### 2.8 请求失败和限流保护

- 对 403、429、5xx、连接超时和读取超时分类处理。
- 使用指数退避并加入随机抖动。
- 检测状态码为 200 的验证页、登录页和异常空页面。
- 连续失败后降低该站并发。
- 达到阈值后暂停或终止该站本轮任务。
- 单站熔断不得影响其他站点。

#### 2.9 代理检测与自动直连

- 爬取前检测 127.0.0.1:7890 是否可连接。
- 代理不可用时立即采用直连，不等待多次超时。
- 日志明确显示代理或直连模式。
- 图片下载与页面请求使用一致、可观察的代理策略。
- 代理恢复后是否自动切回需要谨慎处理，本阶段默认仅在新任务启动时检测。

#### 2.10 SQLite 并发保护

- 启用 WAL。
- 设置 busy_timeout。
- 增加写入锁和 database is locked 重试。
- 帖子插入、图片字段更新和任务状态更新保持一致。
- 确保统计数量与实际入库数量一致。
- 必要时再升级为独立写入队列。

#### 2.11 图片后台队列

- 详情解析先获得核心数据和原始图片 URL。
- 有下载链接的帖子优先入库。
- 图片进入全局固定线程池下载。
- 下载成功后安全更新 images 字段。
- 下载失败保留远程 URL，允许重新下载。
- 区分“核心数据完成”和“图片同步完成”。
- 同一 URL 和同一帖子避免重复排队。

### P1：任务生命周期

#### 2.12 历史任务残留 running

当前任务 #11、#13 状态残留 running。正确处理方式：

- 程序启动时识别上次遗留的 running 任务。
- 当前引擎没有运行时，将其标记为 interrupted。
- 记录结束时间和中断原因。
- 正常完成使用 completed。
- 用户停止使用 cancelled。
- 未处理异常使用 failed。
- 前端历史记录支持显示以上状态。

历史任务更新前先备份数据库，并只修改明确的异常任务状态。

#### 2.13 Flask调试模式和重复执行

- 日常一键启动默认关闭 debug。
- 关闭自动重载器，避免线程和任务重复启动。
- 需要开发调试时通过明确配置开启。
- 同一时刻只允许一个总爬取任务运行。

### P1：安全与配置

#### 2.14 明文登录凭据

当前 config.yaml 含萌幻 ACG 登录凭据。处理要求：

- 真实密码迁移到不提交的本地环境配置。
- 提供不含真实值的示例文件。
- 将本地敏感配置加入 .gitignore。
- 检查 Git 历史是否出现过凭据。
- 不在日志、报告、测试输出和交接文档中复制真实密码。
- 建议用户更换已经暴露到仓库历史的密码。

#### 2.15 图片代理接口安全

检查 /api/proxy_image：

- 仅允许 http 和 https。
- 拒绝 localhost、环回、私有、链路本地和保留 IP。
- 校验重定向后的目标地址。
- 限制响应大小、类型和超时时间。
- 防止将接口用作任意 SSRF 代理。

### P2：版本库和运行产物

#### 2.16 Git脏文件和缓存

- .gitignore 增加 __pycache__/、*.pyc、*.pyo、*.pyd。
- 只从 Git 索引取消跟踪缓存，不删除本机运行文件。
- 数据库、图片、日志、导出目录和本地敏感配置不进入代码提交。
- 修改前先记录当前 git diff，避免覆盖用户已有修改。
- 不擅自提交、重置或清除用户现有改动。

#### 2.17 旧导出文件

output 目录存在 PC.html、PC+安卓.html、仅安卓.html 和新版 ZIP 等历史产物。

处理原则：

- 先生成文件清单并标记当前有效产物。
- 未经用户确认不删除文件。
- 后续需要清理时先备份并移动到回收站。
- 新导出使用隔离临时目录，防止旧图片混入新 ZIP。
- 导出完成后原子替换最终文件。

### P2：数据库脏数据审计

生成只读审计结果，至少统计：

- 总记录数及按站点、平台、批次分布。
- 无百度和移动云盘链接的记录。
- 有解压码但无下载链接的记录。
- 点赞为 0、点赞未知及异常负数记录。
- unknown 平台记录。
- images 为空、JSON 无效、本地文件不存在的记录。
- source + source_id 重复记录。
- crawl_id 为空或引用异常的记录。
- tasks 中 running、failed 和统计不一致的记录。
- 数据库记录与实际图片目录孤儿文件。

审计阶段只输出报告，不删除、不重写业务数据。
